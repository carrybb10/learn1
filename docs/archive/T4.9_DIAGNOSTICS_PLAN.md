# T4.9 高效反馈系统 开发大纲

> 创建：2026-10-03
> 目标：解决"闪退了""白屏了"等无法定位的问题，缩短反馈循环，提升开发效率

---

## 一、为什么需要 T4.9

### 当前反馈链路的痛点

| 环节 | 现状 | 问题 |
|------|------|------|
| 修改→编译 | 手动改代码+单线程编译 | 每次2-5分钟 |
| 用户测试 | 手动运行exe，复现问题 | 依赖用户操作 |
| 反馈 | 截图+描述+上传diag.log | 信息不完整，反复追问 |
| 定位 | 读日志+猜原因 | 很多问题需要多轮试错 |
| 验证 | 再编译→再测试 | 循环周期长 |

### 典型无法定位的问题
- "闪退了" — 无调用栈，无法知道崩溃在哪一行
- "白屏了" — 无渲染状态，无法知道是交换链失败还是着色器失败
- "卡住了" — 无线程状态，无法知道是死锁还是IO阻塞
- "翻译不对" — 无模型输入输出，无法知道是prompt问题还是模型幻觉

## 二、T4.9 四大模块

### 模块1：结构化日志系统（Logger）

**目标**：替代当前散乱的 qDebug/fprintf，提供分级、分类、线程安全的日志。

#### 设计
```
Logger (单例)
  ├─ 级别：TRACE / DEBUG / INFO / WARN / ERROR / FATAL
  ├─ 模块：DECODER / RENDERER / AUDIO / SUBTITLE / AI_ASR / AI_MT / UI / CORE
  ├─ 输出：stderr（控制台）+ 文件（自动轮转）
  └─ 线程安全：内部 mutex，任意线程可调用
```

#### API
```cpp
LOG_INFO(RENDERER, "Swap chain created: %dx%d", width, height);
LOG_WARN(DECODER, "Decode failed: %d", ret);
LOG_ERROR(AI_MT, "llama_memory_clear failed");
```

#### 文件输出
- 路径：`logs/mediaplayer_YYYYMMDD_HHMMSS.log`
- 单文件上限 10MB，最多保留 5 个历史文件
- 格式：`[时间] [级别] [模块] [线程ID] 消息`

#### 运行时控制
- 环境变量 `MEDIAPLAYER_LOG_LEVEL=DEBUG` 控制级别
- 诊断面板可动态调整级别

---

### 模块2：崩溃捕获（CrashHandler）

**目标**：程序崩溃时自动保存调用栈和上下文，替代"闪退了"三个字。

#### 设计
```
CrashHandler (启动时注册)
  ├─ SetUnhandledExceptionFilter 捕获 SEH 异常
  ├─ 生成 minidump（调用栈+寄存器+内存）
  ├─ 保存崩溃前最后 200 行日志
  ├─ 写入 crash_report_YYYYMMDD_HHMMSS.txt
  └─ 下次启动时提示"上次异常退出，是否查看报告"
```

#### 崩溃报告内容
```
=== MediaPlayer Crash Report ===
时间：2026-10-03 14:23:01
版本：v0.4.8 (build xxx)
系统：Windows 11 23H2, CPU i7-13700HX, GPU NVIDIA RTX 4060
异常代码：0xC0000005 (ACCESS_VIOLATION)
异常地址：0x00007FF612345678 (MediaPlayer.exe!D3D11Renderer::present+0x42)

--- 调用栈 ---
0: D3D11Renderer::present (D3D11Renderer.cpp:234)
1: VideoWidget::render (VideoWidget.cpp:89)
2: QTimer::timeout (Qt6Core)
...

--- 最后日志 ---
[14:23:01.123] [INFO] [RENDERER] Swap chain created: 1920x1080
[14:23:01.456] [WARN] [DECODER] D3D11VA lock callback timeout
[14:23:01.789] [ERROR] [RENDERER] ResizeBuffers failed: -2005270523
```

#### 技术选型
- Windows API：`SetUnhandledExceptionFilter` + `MiniDumpWriteDump`
- 调用栈：`StackWalk64`（DbgHelp.dll）
- 零外部依赖，纯 Win32 API

### 模块4：一键导出诊断包（DiagnosticExporter）

**目标**：用户点一个按钮，自动打包所有调试信息，直接发给开发者。

#### 导出内容
```
diagnostic_YYYYMMDD_HHMMSS.zip
  ├─ system_info.txt      — CPU/GPU/内存/OS/驱动版本
  ├─ config.txt           — 当前配置（硬件解码/分辨率/音量/AI设置）
  ├─ player_state.txt     — 播放状态快照（当前文件/位置/队列状态）
  ├─ logs/
  │   ├─ current.log      — 当前会话完整日志
  │   └─ previous.log     — 上一会话日志（如果有）
  ├─ crash_reports/       — 最近的崩溃报告（如果有）
  │   └─ crash_xxx.txt
  └─ README.txt           — 说明文件（版本号+导出时间+如何反馈）
```

#### 触发方式
1. 诊断面板内的"导出"按钮
2. 快捷键 `Ctrl+E`
3. 命令行参数 `--export-diagnostic`

#### 技术实现
- 系统信息：Windows API（GetSystemInfo、GlobalMemoryStatusEx、DirectX 诊断）
- 压缩：Qt 自带 QSaveFile + 手动 zip（或用 miniz 单头文件库）
- 输出路径：桌面 `mediaplayer_diagnostic_xxx.zip`

## 三、实施顺序

### Phase 1：基础日志 + 崩溃捕获（核心，优先）
1. 创建 Logger 类，替换关键路径的 qDebug/fprintf
2. 创建 CrashHandler，启动时注册
3. 崩溃时自动生成报告
4. 编译验证崩溃捕获有效

### Phase 2：诊断面板
1. 创建 DiagnosticPanel 窗口（独立 QDialog）
2. 实现状态数据采集（从 PlayerController/Logger 拉取）
3. 实时刷新（500ms 定时器）
4. 日志实时显示+过滤
5. Ctrl+D 快捷键绑定

### Phase 3：一键导出
1. 创建 DiagnosticExporter
2. 收集系统信息+配置+状态+日志
3. 打包为 zip
4. 诊断面板内添加导出按钮
5. Ctrl+E 快捷键绑定

### Phase 4：完善与优化
1. 所有模块统一使用 Logger
2. 崩溃报告包含更多上下文（当前播放文件元数据）
3. 诊断面板添加图表（帧率曲线、队列占用曲线）
4. 自动检测已知问题并给出建议（如"检测到D3D11设备丢失，建议重启播放器"）

## 五、与现有代码的集成点

| 现有模块 | 集成方式 |
|----------|----------|
| main.cpp | 启动时初始化 Logger + CrashHandler，注册 Ctrl+D/Ctrl+E 快捷键 |
| PlayerController | 关键操作用 LOG_* 替换 qDebug，提供状态快照接口 |
| D3D11Renderer | 渲染错误用 LOG_ERROR，提供 D3D11 状态查询接口 |
| WhisperTranscriber | 识别过程用 LOG_INFO/AI_ASR |
| Translator | 翻译过程用 LOG_INFO/AI_MT，记录 prompt 和输出 |
| CMakeLists.txt | 链接 DbgHelp.lib（崩溃捕获需要） |

## 六、验收标准

1. **日志**：运行后 `logs/` 目录生成日志文件，格式正确，包含级别/模块/线程ID
2. **崩溃捕获**：故意触发空指针访问，程序退出后 `crash_reports/` 生成报告，包含调用栈
3. **诊断面板**：Ctrl+D 调出，实时显示帧率/队列/D3D11状态/AI状态，数据与实际一致
4. **一键导出**：Ctrl+E 在桌面生成 zip，解压后包含系统信息+配置+日志+状态
5. **不影响播放**：诊断系统运行时 CPU 占用 < 1%，不影响视频播放流畅度
