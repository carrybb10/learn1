# T4.8 离线AI翻译字幕 — 策划方案与实施路线图

> 创建日期：2026-10-02
> 目标路径：Whisper.cpp (ASR) + Index-Translate 2B (翻译)
> 最终形态：几乎实时的离线多语言翻译字幕，与无损播放器深度融合

---

## 一、产品愿景

**打造一款"带脑子"的无损视频播放器**：在原帧率原音质播放的基础上，内置离线AI能力，无需联网即可将任意语言视频的语音实时识别并翻译为目标语言字幕。

**核心差异化**：
- 真正离线：视频不出本机，隐私安全
- 无损播放：D3D11零拷贝 + 音频直通，不牺牲画质音质
- 多语言互译：150种语言，覆盖绝大多数视频内容
- 免费开源：无订阅、无API调用费、无使用次数限制

## 三、理想实现效果（用户体验）

### 3.1 一键开启
```
播放视频 → 点"AI字幕"按钮 → 选择目标语言(如中文)
  → 3-5秒后字幕开始出现（比音频延迟3-5秒）
  → 全程自动识别+翻译，无需任何其他操作
```

### 3.2 双字幕显示
- 上方：原文（Whisper识别结果）
- 下方：译文（Index-Translate翻译结果）
- 可切换：仅原文 / 仅译文 / 双语对照
- 字幕位置可拖动（复用现有DraggableLabel）

### 3.3 实时性指标
| 阶段 | 延迟目标 | 说明 |
|------|----------|------|
| 首句字幕出现 | <5秒 | 从开启AI字幕到第一句译文显示 |
| 句间延迟 | 3-5秒 | 上一句说完后3-5秒显示译文 |
| 长视频稳定性 | 无累积延迟 | 全程保持3-5秒延迟，不越播越慢 |

### 3.4 模型管理
- 首次使用提示下载模型（ASR + 翻译共约1.7GB）
- 支持多档模型选择：
  - **轻量档**：Whisper tiny(75MB) + Index-Translate 2B int4(~1GB) = ~1.1GB，CPU可跑
  - **平衡档**：Whisper base(142MB) + Index-Translate 2B Q4(~1.5GB) = ~1.7GB，推荐
  - **高质量档**：Whisper small(466MB) + Index-Translate 2B Q8(~3GB) = ~3.5GB，GPU推荐
- 模型下载支持断点续传、校验、更换存储路径

### 3.5 结果缓存
- 识别+翻译结果自动保存为 `.srt`（同目录同名）
- 下次播放同一视频直接加载缓存，零延迟
- 可导出字幕文件（SRT/ASS）

## 四、技术架构

### 4.1 整体管线

```
视频播放
  │
  ├─ FFmpeg 解码音频 → PCM 数据
  │     │
  │     ├─ 复制一份到 AI 处理管线（不影响播放）
  │     │
  │     └─ 环形缓冲（保留最近30秒音频）
  │           │
  │           ├─ Silero VAD 检测语音边界
  │           │     └─ 句子结束(静音>500ms) → 触发识别
  │           │
  │           ├─ Whisper.cpp 流式识别
  │           │     ├─ 输入：16kHz mono float32 音频段
  │           │     ├─ 输出：原文 + 时间戳
  │           │     └─ 模型：base(默认) / tiny(快速) / small(高质量)
  │           │
  │           └─ Index-Translate 2B 翻译
  │                 ├─ 输入：原文句子 + 源语言/目标语言
  │                 ├─ 输出：译文句子
  │                 └─ 推理：llama.cpp / CTranslate2
  │
  └─ 字幕显示管线（复用现有 SubtitleParser + DraggableLabel）
        ├─ 原文轨道：Whisper 输出直接显示
        └─ 译文轨道：翻译结果显示，可切换显示模式
```

### 4.2 模块划分

| 模块 | 职责 | 技术 |
|------|------|------|
| AudioTap | 从解码管线复制PCM，重采样为16kHz mono | FFmpeg swresample |
| VADSegmenter | 语音活动检测，切分句子 | Silero VAD (ONNX Runtime) |
| WhisperTranscriber | 语音识别，输出带时间戳文本 | whisper.cpp (GGUF) |
| Translator | 机器翻译，句子级翻译 | llama.cpp + Index-Translate 2B |
| SubtitleComposer | 合并原文+译文，管理显示时序 | 复用 SubtitleParser 扩展 |
| ModelManager | 模型下载、校验、切换、存储路径 | Qt Network + QSettings |
| CacheManager | 识别结果缓存为SRT，下次直接加载 | 文件IO |

### 4.3 线程模型

```
主线程：UI + 视频渲染 + 字幕显示
  │
  ├─ AI调度线程：管理VAD分段、调度识别/翻译任务
  │
  ├─ Whisper识别线程：阻塞式whisper_full，完成后发信号
  │
  └─ 翻译线程：阻塞式llama.cpp推理，完成后发信号
```

- 识别和翻译**并行流水线**：第N句在翻译时，第N+1句可以同时识别
- 不阻塞播放主线程，AI计算全部在后台

### 4.4 关键技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| ASR | **Whisper.cpp** | 99语言，C/C++原生，GGUF量化，CPU/GPU均可，生态最成熟 |
| VAD | **Silero VAD** | ONNX格式仅2MB，准确率高，延迟低 |
| 翻译 | **Index-Translate 2B** | Apache 2.0，150语言，视频/网络梗优化，Qwen3.5底座中文强 |
| 翻译推理 | **llama.cpp** (优先) / CTranslate2 | 与Whisper同生态，GGUF支持好，C/C++可直接链接 |
| 模型格式 | **GGUF (Q4_K_M)** | 2B模型Q4约1.5GB，质量损失小，CPU推理可接受 |

## 五、分阶段实施路线图

### Phase 1：离线完整识别+翻译（验证效果）
**目标**：跑通完整管线，验证翻译质量，不要求实时

| 步骤 | 内容 | 预计工作量 |
|------|------|-----------|
| 1.1 | 集成 whisper.cpp，CMake add_subdirectory | 中 |
| 1.2 | 实现 AudioTap：从解码管线提取音频→16kHz mono→WAV | 中 |
| 1.3 | 实现离线完整识别：播放前/后台识别整个音频文件 | 中 |
| 1.4 | 集成 llama.cpp + Index-Translate 2B GGUF | 中 |
| 1.5 | 实现句子级翻译（批量翻译识别结果） | 小 |
| 1.6 | 扩展 SubtitleParser 支持双轨字幕（原文+译文） | 中 |
| 1.7 | UI：AI字幕开关 + 目标语言选择 | 小 |
| 1.8 | 识别结果缓存为SRT | 小 |

**交付标准**：打开视频→开启AI字幕→等待（视频时长的0.3-0.5倍）→双语字幕正常显示，翻译质量可接受

### Phase 2：VAD分段准实时（延迟5-10秒）
**目标**：播放中后台识别已播放内容，字幕延迟5-10秒出现

| 步骤 | 内容 | 预计工作量 |
|------|------|-----------|
| 2.1 | 集成 Silero VAD (ONNX Runtime) | 中 |
| 2.2 | 实现环形音频缓冲 + VAD实时分段 | 中 |
| 2.3 | 改造 WhisperTranscriber 为分段流式识别 | 中 |
| 2.4 | 识别-翻译流水线并行（第N句翻译时识别第N+1句） | 中 |
| 2.5 | 字幕实时显示（识别翻译完成立即追加显示） | 小 |
| 2.6 | 进度反馈：显示"AI识别中..."状态 | 小 |

**交付标准**：播放视频→开启AI字幕→首句5-10秒后出现→后续句子持续出现→全程延迟稳定5-10秒

### Phase 3：接近实时优化（延迟3-5秒）
**目标**：延迟压到3-5秒，体验接近实时

| 步骤 | 内容 | 预计工作量 |
|------|------|-----------|
| 3.1 | Whisper 流式识别（不等待整句，部分识别+修正） | 大 |
| 3.2 | 翻译前缀解码（句子未识别完就开始翻译） | 大 |
| 3.3 | GPU推理加速（Vulkan/CUDA后端） | 中 |
| 3.4 | 模型量化优化（int4/int3，CTranslate2对比） | 中 |
| 3.5 | 推测性解码（小模型草拟+大模型修正） | 大 |
| 3.6 | 重复句子缓存（相同句子不重复翻译） | 小 |

**交付标准**：首句<5秒，句间延迟3-5秒，CPU机型可流畅运行，GPU机型接近实时

**目标**：降低使用门槛，准备发布

| 步骤 | 内容 |

## 六、模型体积与性能预算

### 6.1 模型体积

| 档位 | ASR模型 | 翻译模型 | 总计 | 适用场景 |
|------|---------|----------|------|----------|
| 轻量 | tiny 75MB | 2B int4 ~1.0GB | ~1.1GB | 低配置CPU，快速预览 |
| 平衡(推荐) | base 142MB | 2B Q4_K_M ~1.5GB | ~1.7GB | 主流CPU，质量速度平衡 |
| 高质量 | small 466MB | 2B Q8 ~3.0GB | ~3.5GB | 有GPU，追求质量 |

### 6.2 性能预算（平衡档，CPU推理）

| 操作 | 耗时预算 | 说明 |
|------|----------|------|
| VAD分段 | <10ms | 极快，可忽略 |
| Whisper base 识别(5秒音频) | ~0.5-1s | 约0.1x实时 |
| Index-Translate 2B 翻译(20词) | ~0.3-0.5s | 约15-30 tok/s |
| 单句总处理 | ~1-1.5s | 从句子结束到译文显示 |
| 加上VAD等待 | 3-5s | 句子本身2-3s + 处理1-1.5s |

### 6.3 内存预算

| 组件 | 内存占用 |
|------|----------|
| 播放器本体 | ~200-500MB |
| Whisper base 模型 | ~300MB（运行时） |
| Index-Translate 2B Q4 | ~2GB（运行时） |
| 音频缓冲+临时数据 | ~100MB |
| **总计** | **~2.5-3GB** |

> 最低内存要求：8GB（推荐16GB）

## 七、风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 翻译质量不如在线大模型 | 用户体验下降 | 明确标注"离线翻译"，提供导出后用在线工具润色选项 |
| CPU推理速度不够 | 延迟过高 | 多档模型选择，GPU加速，轻量档兜底 |
| 模型下载流失 | 用户不愿下载1.7GB | 模块化下载，先用在线翻译过渡，离线作为高级功能 |
| Whisper识别错误传播 | 翻译错上加错 | 识别结果置信度过滤，低置信度标记为"[可能不准确]" |
| 长视频内存溢出 | 崩溃 | 分段处理，及时释放已翻译句子的内存 |
| 多语言自动检测错误 | 翻译方向错误 | 允许手动指定源语言，自动检测作为默认 |
